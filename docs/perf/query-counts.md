# عدّ استعلامات Prisma لكل طلب

يُفعّل عدّ الاستعلامات فقط للتشغيلة التشخيصية القصيرة عبر `PERF_QUERY_COUNT_ENABLED=true`. يبقى مطفأً في warm-up وتشغيلات قياس latency لتجنب تأثير التسجيل على p95. يسجل التطبيق بعد اكتمال كل طلب HTTP سطرًا بصيغة JSON يبدأ بـ`[query-count]` ويحتوي على method والمسار وحالة HTTP وعدد عمليات Prisma التي مرّت خلال سياق الطلب.

تشغيلة `K6_QUERY_COUNT=true` تستخدم VU واحدًا يتناوب بين endpoints لمدة دقيقة، مع تعطيل العداد في warm-up وتشغيلات latency. سجل العينة النهائية: `results/query-count-sample-final-query-counts.log`؛ نجحت الطلبات الـ706 دون أخطاء. الطلبات الداخلية `/internal/*` تظهر كسجلات مستقلة ولا تدخل في عدّ الطلب الخارجي.

| Endpoint | الاستعلامات لكل طلب (baseline) | عدد العينات |
|---|---:|---:|
| `GET /products` | 2 | 172 |
| `GET /products/:id` | 1 | 171 |
| `GET /orders` | 2 | 171 |
| `POST /orders` | 1 | 171 |

هذه الأرقام تعدّ عمليات Prisma على مستوى التطبيق، وليست عدًّا مضمونًا لكل SQL statement يصدره Prisma أو الطلبات الداخلية. أظهر تدقيق `/orders` عدم وجود استعلام Prisma داخل loop، لكن خطة SQL لقراءة `items` على صفحة من 20 طلبًا كانت تمسح جدول `order_items` كاملًا حتى إضافة فهرس `orderId` المقترحة.
